## Después de `/revisar` (commit `fix`)

Una corrida de `pnpm check` en medio de los cambios dio 22 tests fallidos de 222. No guardé la salida, y no pude
reproducirlo en cinco corridas más, incluidas dos en paralelo. Todas pasaron:

```
$ pnpm check            # dos veces
      Tests  222 passed (222)
   Duration  24.70s
      Tests  222 passed (222)
   Duration  24.39s
$ pnpm exec vitest run  # dos a la vez
      Tests  222 passed (222)
      Tests  222 passed (222)
```

La causa más probable es un timeout bajo carga: cada test de la base levanta su propio Postgres (PGlite) y aplica la
migración. `vitest.config.ts` ahora da 20 s por test y 30 s por hook. Eso solo cambia el tiempo de espera, no lo que
cada test comprueba. Si vuelve a pasar en CI, hay que guardar la salida y mirar la causa real.

Tests nuevos de los hallazgos:
- `apps/api/test/app.test.ts`:
  - "refuses a connection a third party started, finished in the victim's session (CSRF)";
  - "a wallet cannot revoke an athlete another wallet still relies on";
  - "accepts an EVM contract address in any case";
  - "refuses a body over the size limit".
- `apps/api/test/strava-tokens.test.ts`:
  - "does not revoke when it lost a race and Strava refused its stale refresh token";
  - "does not call a missing connection a revocation";
  - "reports a revoked connection as revoked".
- `packages/db/test/repository.test.ts`, la suite de "purgeExpiredData":
  - un `dry-run` y después `live` de la misma posición;
  - el atleta anulado tras el `live`;
  - las conexiones revocadas a los 30 días;
  - los desafíos y las sesiones vencidos.

La migración se regeneró como una sola, `packages/db/drizzle/0000_init.sql` (8 tablas). La rama no estaba mergeada y
ninguna base la había aplicado.
